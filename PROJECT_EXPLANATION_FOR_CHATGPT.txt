1. PROJECT OVERVIEW & VISION
================================================================================
Project Name: FlashGuard Pro (also includes "FraudGuard" mobile interface)
Repository: Project_FlashGuard
Domain: FinTech / CyberSecurity / AI Fraud Detection

Vision:
FlashGuard Pro is an end-to-end, real-time financial surveillance & fraud detection 
platform designed to protect digital transactions using machine learning, 
behavioral pattern analysis, rule-based heuristics, and instant risk scoring.

The system combines:
1. High-Performance ML Inference Backend (FastAPI + Python + SQLite + WebSockets)
2. Live Administrative Surveillance Dashboard (React + Vite + Recharts + Tailwind CSS)
3. End-User Mobile Payment App Simulator (React + Vite + Custom CSS Phone Frame)
4. Automated Live Bank Transaction Streamer (Simulates real-time transaction feeds)
5. ML Training & Feature Engineering Pipeline (Scikit-Learn + PaySim Dataset)

2. SYSTEM ARCHITECTURE & COMPONENTS
================================================================================

The repository is structured into four main subsystems:

--------------------------------------------------------------------------------
A. BACKEND (`/backend`)
--------------------------------------------------------------------------------
- Framework: FastAPI (Python 3.x), Uvicorn ASGI Server
- Data Store: SQLite (`flashguard.db`) with persistent logging (`redis_logger.py` & `database.py`)
- Key Modules:
  * `main.py`: Main API entry point. Implements CORS middleware, HTTP rate-limiting on `/predict` (2-second interval check per IP), WebSocket broadcast manager (`/ws/alerts`), and REST endpoints.
  * `predict.py`: Core fraud inference engine combining ML model predictions (`flashguard_model.pkl`) with rule-based heuristics, velocity checks, and risk score calculation (0–100 scale).
  * `behavioral_model.py`: User-level behavioral tracking and anomaly detection comparing current transaction against historical user patterns.
  * `feedback.py`: Dynamic feedback loop allowing post-transaction learning/adjustments to risk scoring models.
  * `streamer.py`: Live data streamer script replaying historical PaySim dataset transactions into the REST API at configurable intervals.
  * `seed_paysim.py`: Database initialization script to seed sample transaction data on backend startup.
  * `schemas.py`: Pydantic data schemas for request payloads, risk responses, and stats.
- Key API Endpoints:
  * `POST /predict`: Evaluates transaction payload, returns risk score (0-100), decision (ACCEPT/REVIEW/BLOCK), status (SAFE/SUSPICIOUS/FRAUD), risk reasons, amount deviation, and behavioral insights.
  * `GET /history`: Retrieves logged transaction history for dashboard charts.
  * `GET /dashboard/stats`: Returns overall network metrics (total txns, blocked today, average txn amount, fraud detection rate, risk distribution counts).
  * `GET /transactions`: Queryable transaction logs with status filtering and limit controls.
  * `GET /dashboard/chart-data`: Hourly trend data and category-wise spending totals.
  * `WebSocket /ws/alerts`: Real-time websocket stream broadcasting new transactions & risk assessments to connected clients.

--------------------------------------------------------------------------------
B. ADMIN ANALYTICS DASHBOARD (`/Frontend`)
--------------------------------------------------------------------------------
- Technology Stack: React.js, Vite, Tailwind CSS, Recharts, Lucide Icons.
- Purpose: Admin surveillance center for monitoring platform health and suspicious transactions.
- Key Capabilities:
  * Real-Time Transaction Throughput Monitoring (Live charts updating via WebSocket/polling).
  * Category Spending Breakdown (Transfers, Cash-out, Payments, Crypto, etc.).
  * System Health Radar (Multi-dimensional view of Risk, Volume, Trust, and Diversity).
  * Audit Trail & Live Fraud Alerts Feed.
  * Proxy Configuration: Configured via Vite proxy to route `/api` requests seamlessly to backend `http://localhost:8000`.

--------------------------------------------------------------------------------
C. MOBILE END-USER PAYMENT APP (`/fraudguard`)
--------------------------------------------------------------------------------
- Technology Stack: React 18, Vite 5, Custom CSS Design System, Responsive Breakpoints.
- Design & Experience:
  * Native smartphone shell frame simulation for desktop screens, switches to full-screen native mobile layout on actual mobile viewports (< 520px).
  * Includes iOS-style live status bar, bottom navigation tab bar, biometrics login screen.
- Key Screens & Features:
  * `LoginScreen`: Biometric authentication simulation.
  * `HomeScreen`: Wallet balance, recent transactions, quick actions.
  * `SendMoneyScreen`: Peer-to-peer money transfers with real-time dynamic fraud risk warning.
  * `FraudAnalysisScreen`: Animated 11-stage fraud detection pipeline visualization (evaluates amount spike, velocity, location anomaly, merchant risk, VPN/IP check, etc.).
  * `HistoryScreen`: Filterable transaction history.
  * `InsightsScreen` & `SpendingScreen`: Visual analytics and AI spending insights.
  * `CardManagementScreen`: Virtual card control, freeze card toggle, spending limits.
  * `SecurityCenterScreen`: Active threat feeds, connected device manager.
  * `InternationalScreen` & `SplitBillScreen`: FX currency converter and bill splitting.

--------------------------------------------------------------------------------
D. ML & DATA PIPELINE (`/ML & Data` & root scripts)
--------------------------------------------------------------------------------
- Dataset: PaySim synthetic financial dataset for fraud detection (evaluating TRANSFER, CASH_OUT, PAYMENT types).
- Notebook (`ML & Data/notebook/fraud_model.ipynb`): Exploratory Data Analysis (EDA), correlation analysis, feature engineering (balance ratios, step features, velocity), and model comparisons.
- Model Training Scripts (`ML & Data/training/train_paysim.py`, `train_model.py`):
  * Feature extraction: `amount`, `oldbalanceOrg`, `newbalanceOrig`, `oldbalanceDest`, `newbalanceDest`, `type`, velocity, balance delta checks.
  * Model Architecture: Random Forest / XGBoost classifiers saved into `flashguard_model.pkl`.
  * Helper scripts: `rescue_model.py`, `train_fast.py` for rapid re-training.

3. FRAUD DETECTION LOGIC & 11-LAYER RISK ENGINE
================================================================================

The system uses a hybrid approach combining machine learning inference with an 
11-layer heuristic rule engine:

1. High Amount Spike Detection (Compares transaction vs. historical user average)
2. Late-Night / Unusual Hour Activity
3. Velocity Spike (Multiple transactions within a short window)
4. Location / Geo Anomaly (Unexpected location or country mismatch)
5. Round Amount / Arbitrage Pattern Detection
6. Merchant & Category Risk Scoring (High risk assigned to crypto, wire transfers)
7. Device Fingerprint Mismatch
8. IP & Proxy Risk (Detection of VPN/Tor exit nodes)
9. Account Trust Score History
10. Failed Login History & Password Reset Correlations
11. ML Model Probability Score (Random Forest output on engineered features)

Output Schema:
- Risk Score: 0 - 100
- Risk Level: SAFE (0-40) | SUSPICIOUS (41-80) | FRAUD (81-100)
- Decision: ACCEPT | REVIEW | BLOCK
- Reasons Array: Detailed human-readable flags explaining why risk score was escalated.
